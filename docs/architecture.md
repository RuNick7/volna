# Navidrome-клиент «как Яндекс Музыка»: архитектура и алгоритм «Моей волны»

Дата: 31.10.2026. Статус: исследование; дизайн интерфейса будет позже.

---

## 1. Что уже есть в инфраструктуре

### Navidrome (Subsonic / OpenSubsonic API)

| Что | Эндпоинт | Зачем нам |
|---|---|---|
| Стриминг | `stream`, `getCoverArt` | воспроизведение |
| Учёт прослушиваний | `scrobble` (`submission=false` значит «сейчас играет», `true` значит «прослушано»; параметр `time` для офлайн-прослушиваний) | play count и last played общие для всех клиентов и для AudioMuse |
| Лайки | `star` / `unstar`, `getStarred2` | сильный позитивный сигнал |
| Рейтинг | `setRating` | договорённость: 1★ = «не нравится» |
| Очередь | `getPlayQueue` / `savePlayQueue` (+ `…ByIndex`, если сервер объявляет расширение Index based Queue) | продолжить слушать на другом устройстве |
| Плейлисты | `getPlaylists`, `createPlaylist`, `updatePlaylist` | |
| Похожие | `getSimilarSongs2` (через плагин AudioMuse) | только от **одного** трека: отсюда и проблема «подбор по последней песне» |
| Звучание | `getSonicSimilarTracks(id)`, `findSonicPath(startSongId, endSongId)` | OpenSubsonic-расширение `sonicSimilarity`, работает при активном плагине |

**Чего нет в Subsonic:** событий «пропустил» и «бросил на 20-й секунде». А для волны это главный сигнал, поэтому хранить его придётся самим (см. §6–7).

### AudioMuse-AI (REST на порту 8000, заголовок `Authorization: Bearer <API_TOKEN>`)

Для каждого трека AudioMuse считает: эмбеддинг MusiCNN (200 чисел), эмбеддинг CLAP (512 чисел), tempo, energy, тональность и `mood_vector` (danceable, aggressive, happy, party, relaxed, sad).

| Эндпоинт | Что делает | Роль в приложении |
|---|---|---|
| `GET /api/similar_tracks?item_id&n&eliminate_duplicates&mood_similarity` | похожие на один трек | быстрые кандидаты, фолбэк |
| `POST /api/alchemy` `{items:[{id, op: ADD\|SUBTRACT, type: song\|artist\|mood\|playlist\|anchor}], n, temperature, subtract_distance}` | поиск сразу вокруг нескольких точек, с вычитанием нелюбимого и сэмплингом по температуре | **ядро волны и продолжения плейлиста** |
| `GET /external/get_embedding?id=` | вектор трека (принимает id из Navidrome) | профиль вкуса |
| `GET /external/get_score?id=` | tempo, energy, key, mood | переранжирование, плавные переходы |
| `POST /api/clap/search` | поиск по текстовому описанию («calm piano for focus») | режимы «Занятие» и «Настроение» |
| `GET /api/find_path` | плавный переход между двумя треками | переход между «кластерами» вкуса |
| `/api/sonic_fingerprint/generate` | топ прослушанных с весом по давности, затем соседи | холодный старт |
| `/api/anchors`, `/api/radios` | сохранённые смеси; регулярно пересобираемые плейлисты | при желании можно сделать «серверные волны» |

**Ключевая деталь Alchemy:** тип `playlist` не усредняет плейлист в одну точку. Он сводит плейлист к нескольким центроидам (`ALCHEMY_PLAYLIST_MAX_CENTROIDS`), и каждая точка получает свою квоту кандидатов. Поэтому плейлист из рока и электроники не превращается в «что-то посередине», а это ровно то, что нужно.

## 2. Почему другие приложения «скатываются»

* **Радио от последнего трека** работает как случайное блуждание: каждый следующий трек ищется от предыдущего, ошибка накапливается, и через 20 треков вы уже далеко от исходного плейлиста.
* **Усреднение всего плейлиста в одну точку** уходит в другую крайность: центр масс разнородного плейлиста часто оказывается в месте, где нет ничего, что вам нравится.

**Решение: якорь не двигается.** Профиль строится один раз из всего контекста (плейлист или вся история) в виде *нескольких* центроидов. Каждая новая порция ищется от этих якорей. Последние треки и ваша реакция на них меняют только *веса*, но не подменяют якорь.

## 3. Модель вкуса

### Сигналы (начальные веса, потом подбираются по данным)

| Событие | Вес |
|---|---|
| лайк (star) | +3 |
| дослушал (≥ 80 %) | +1 |
| повторные прослушивания | +log(1 + plays) |
| пропуск после 30 с | −0.5 |
| пропуск до 30 с | −1.5 |
| дизлайк (1★) | −5, трек больше никогда не ставится |

Затухание по времени: `w · 0.5^(дней / 60)`.

### Из чего состоит профиль

* **Долгосрочный вкус.** Эмбеддинги позитивных треков → k-means (K ≈ √(N/2), от 4 до 12) → «вкусовые кластеры»: `{центр, вес, медоиды}`, где медоиды — реальные треки, ближайшие к центру. Пересчёт раз в сутки или после 50 новых событий.
* **Негативный профиль.** Последние ~200 дизлайков и ранних пропусков → идут в SUBTRACT.
* **Сессия.** Экспоненциальное скользящее среднее эмбеддингов треков текущей сессии (α = 0.3); пропуски отталкивают вектор.
* **Статистика кластеров.** Для каждого кластера распределение `Beta(дослушал + 1, пропустил + 1)`, отдельно по времени суток (утро, день, вечер, ночь).

## 4. Алгоритм «Моей волны»

Очередь держим короткой: 3–5 треков впереди. Когда их остаётся мало, генерируем 40 кандидатов и берём лучшие 5. Благодаря этому волна реагирует на пропуск уже через 1–2 трека.

```text
next_batch(session):
  # 1. Какой «вкус» играть: Thompson sampling по кластерам
  for c in clusters:
      p[c] = sample(Beta(c.completes + 1, c.skips + 1))   # по текущему времени суток
           * c.weight ** 0.5
           * (1 + β · cos(c.center, session.vector))       # держим настроение сессии
           * session_penalty[c]                             # ×0.6 после пропуска в этом кластере
  chosen = top-2 кластера по p
  с вероятностью 15 % добавить «разведку»: соседний или маленький кластер

  # 2. Кандидаты из AudioMuse
  cands = POST /api/alchemy {
      items: 3 медоида каждого выбранного кластера             → ADD
           + последние 2 дослушанных трека сессии              → ADD
           + негативные медоиды и пропуски сессии              → SUBTRACT,
      n: 40,
      temperature: mode.temperature }

  # 3. Фильтры
  убрать: дизлайки; уже в очереди; игравшие меньше 3 дней назад
          (в режиме «Незнакомое» — игравшие когда-либо);
          того же артиста, что в последних 4 треках; тот же альбом, что в последних 8

  # 4. Оценка «вероятности дослушать»
  score = 0.35·cos(t, session) + 0.30·max_c cos(t, c.center)
        − 0.25·max cos(t, negatives)
        + 0.10·novelty(t) + 0.10·artist_completion_rate(t) − 0.15·skip_rate(t)
        − transition_cost(prev, t)          # скачок tempo / energy / тональности

  # 5. Разнообразие: MMR (λ = 0.7), чтобы не шли 5 одинаковых треков подряд
  # 6. Порядок: жадно по transition_cost (как в AudioMuse tasks/playlist_ordering.py)
  return top 5
```

### Мгновенная обратная связь

* **Пропуск до 30 с:** трек уходит в SUBTRACT сессии, вес кластера ×0.6 до конца сессии, сессионный вектор отталкивается. Из очереди убираем 1–2 следующих похожих трека и дозаполняем.
* **Дослушал:** вес кластера ×1.1, сессионный вектор сдвигается к треку.
* **Лайк:** то же, но сильнее, плюс `star` в Navidrome.

### Этап 2: выучить вероятность по-настоящему

Логируем каждый показ трека: признаки (слагаемые формулы выше, час, день недели, режим, позиция в сессии) и исход (дослушал ≥ 80 % → 1, пропустил → 0). После 2–3 тыс. событий заменяем ручные веса логистической регрессией или LightGBM. Это и есть буквально «вероятность, что вы дослушаете».

### Настройки волны (как в Яндексе)

* **Характер.** «Любимое»: temperature 0.3, разрешены часто играемые треки. «Незнакомое»: temperature 1.0, штраф за уже прослушанное, 30 % разведки. «Популярное» для одного пользователя почти бессмысленно; вместо него лучше «Забытое»: любимые треки, которые не играли больше 60 дней.
* **Настроение.** Фильтр или бонус по `mood_vector` и energy из `get_score`: «Бодрое» — energy выше, happy/party; «Спокойное» — relaxed; «Грустное» — sad.
* **Занятие.** Текстовый CLAP-запрос («energetic workout music», «calm instrumental for focus»); его результаты становятся дополнительным ADD-якорем.

### Холодный старт

Звёзды, `getAlbumList2?type=frequent` и выбор 3–5 любимых артистов при первом запуске (в Alchemy им соответствует `type: artist`).

## 5. Продолжение плейлиста или альбома

Когда очередь закончилась:

1. **Контекст** — все треки исходного плейлиста, а не только последний.
2. **Якоря.**
   * Плейлист Navidrome → `ADD {type: playlist, id}`; AudioMuse сам сведёт его к нескольким центроидам.
   * Очередь, собранная вручную → кластеризуем эмбеддинги её треков на 2–4 группы и берём по 2–3 медоида из каждой → ADD.
3. **SUBTRACT** — треки, пропущенные внутри этого плейлиста, плюс глобальные дизлайки.
4. **Переранжирование:** `0.6·близость к плейлисту + 0.3·долгосрочный вкус + 0.1·сессия`, плюс фильтр по артисту и альбому. Последние прослушанные треки влияют через сессионный вектор, но не становятся якорем.
5. **Якорь фиксирован** на всю «бесконечную» часть: каждая порция заново ищется от исходного плейлиста, а не от последнего добавленного трека. Пропуски и лайки на сгенерированных треках меняют только веса.
6. **В интерфейсе** — разделитель «Дальше — похожее на плейлист» и кнопка «Сохранить как плейлист».

---

### Обновление: смещение вместо жёсткого якоря

В прототипе продолжение плейлиста и волна по треку, альбому, артисту или плейлисту устроены как **личная волна, смещённая к источнику** (`Steer` в `engine.py`).

* **Источник** сводится к 1–4 центрам: те же кластеры, что выше.
* **Порция делится** на две части:
  * доля `steer` (по умолчанию 0.65) ищется рядом с центрами источника, по очереди и пропорционально их размеру, чтобы звучали все части плейлиста;
  * остальное — из кластеров вкуса, причём ближние к источнику выбираются чаще.
* **Вектор сессии** стартует от центра источника. В оценку добавляется слагаемое близости к источнику, умноженное на силу смещения.
* **Ранний пропуск похожего** на источник уменьшает силу смещения (×0.85, «не нравится» — ×0.7) и долю этой части источника. Дослушивание возвращает силу к заданной.
* **Якоря.** Плейлист и альбом держат свои опорные треки, чтобы не уплыть. Волна по одному треку подмешивает дослушанные похожие треки как новые опоры и потихоньку развивается.

**Плейлист по песне** — та же смещённая волна, собранная заранее (`build_mix`): смещение 0.85, недавно игравшие треки разрешены, без обучения. Сохраняется в Navidrome через `createPlaylist`.

## 6. Синхронизация

Источник истины — Navidrome. Всё, чего Subsonic не умеет, хранит собственный сервис.

* **Прослушивания.** `scrobble submission=false` в начале трека, `submission=true` после 50 % или 4 минут. В результате play count и last played общие для веба Navidrome, других клиентов и Sonic Fingerprint в AudioMuse.
* **Оценки.** Лайк ↔ `star`, дизлайк ↔ `setRating 1`.
* **Очередь.** `savePlayQueue` при паузе, смене трека, уходе в фон и раз в 30 с. При запуске `getPlayQueue` и предложение «Продолжить на этом устройстве?». Если сервер объявил расширение Index based Queue — `savePlayQueueByIndex` (корректно работает с повторяющимися треками).
* **Плейлисты.** Создание и изменение через Subsonic.
* **Офлайн.** Звук качает `DownloadManager` из Media3 в свой кэш (`files/downloads`), рядом лежат обложки и тексты песен; плеер читает скачанное из того же кэша по ключу `track:<id>`. Трек держится скачанным, пока у него есть причина: скачан вручную, вместе с альбомом или плейлистом, лайкнут или попал в запас (`GET /api/library/reserve` — часто и недавно слушаемое, обновляется раз в 6 часов). Качаем, пока отвечает сам сервис, а с «только по Wi‑Fi» — пока сеть бесплатная; проверку выхода в интернет из Media3 не используем, домашнему серверу он не нужен. Без связи волна играет скачанное, лайки и прослушивания ложатся в outbox (`files/outbox.json`) и уходят, когда сервис снова отвечает; `/api/events` принимает `at`, а `scrobble` — `time`, поэтому офлайн-прослушивания попадают в историю с правильным временем.
* **События волны** (показ, пропуск, позиция, режим) отправляются в wave-service. Там же хранится профиль, поэтому волна одинакова на телефоне, планшете и будущих клиентах для iOS или веба.

## 7. Архитектура

```text
 Android-приложение (Kotlin, Compose, Media3)
   │  Subsonic API: библиотека, стрим, scrobble, star, очередь, плейлисты
   ├──────────────► Navidrome ──(плагин)──► AudioMuse-AI
   │
   │  /wave/*, /events, /continue
   └──────────────► wave-service (Python, FastAPI, Docker рядом с Navidrome)
                       ├─ Subsonic API Navidrome (история, звёзды, плейлисты)
                       ├─ AudioMuse REST (alchemy, similar, embedding, score, clap)
                       └─ PostgreSQL или SQLite (события, профиль, кэш эмбеддингов)
```

### Зачем отдельный сервис, а не всё в приложении

* Профиль синхронизируется между устройствами без хаков.
* `API_TOKEN` AudioMuse не хранится на телефоне.
* Python с numpy и scikit-learn удобен для кластеризации и обучения модели, а алгоритм можно менять без выпуска новой версии приложения.
* Тот же `/wave` пригодится клиентам для iOS и веба.
* Без сервиса приложение остаётся обычным плеером, а волна упрощается до `getSimilarSongs2` / `getSonicSimilarTracks`.

### Черновик API wave-service

```text
POST /wave/start  {mode, mood?, activity?}                        → {session_id, tracks[5]}
POST /wave/next   {session_id}                                    → {tracks[5]}
POST /events      [{track_id, session_id, type: start|skip|complete|like|dislike,
                    position_ms, duration_ms, ts}]
POST /continue    {context_type: playlist|album|queue, context_id?,
                   track_ids[], played_ids[]}                     → {tracks[10]}
GET  /profile     → кластеры вкуса (для экрана «Ваш вкус»)
```

### Android

* Kotlin, Jetpack Compose, Material 3 (дизайн подставим позже).
* Media3: ExoPlayer и MediaSessionService дают фон, уведомление, экран блокировки, Bluetooth и Android Auto. `SimpleCache` заранее загружает 2–3 следующих трека волны, чтобы не было пауз на мобильном интернете.
* Сеть и данные: Ktor client или Retrofit + OkHttp, kotlinx.serialization, Room, WorkManager, Koin или Hilt, Coil.
* Модули: `core-subsonic`, `core-wave`, `core-player`, `data`, `feature-*` (home, wave, library, player, search, playlists).
* API, модели и упрощённый алгоритм пишем на чистом Kotlin без зависимостей от Android. Тогда позже их можно перенести в Kotlin Multiplatform для iOS.

**Форк или с нуля.** Дизайн будет свой, а волна — центральная функция, поэтому рекомендую писать с нуля на чистой архитектуре и подсматривать решения в открытых клиентах: Navic (Kotlin, Android + iOS), Tempo/Tempus, Ultrasonic, Subtracks. Перед заимствованием кода проверить лицензию: у большинства GPL-3.

## 9. Риски

* **Полнота анализа.** Качество целиком зависит от AudioMuse: треки без анализа не попадут в волну. Нужен регулярный анализ новых поступлений.
* **Версии.** Navidrome, плагин и AudioMuse нужно обновлять вместе (так рекомендует официальная документация).
* **Внутренний API.** Эндпоинты `/api/alchemy` и другие — это не публичный контракт, они могут меняться между версиями. Поэтому в wave-service нужен адаптер, а при обновлении — сверка со Swagger (`/apidocs/`).
* **Один пользователь.** Нет коллаборативной фильтрации («популярное у похожих слушателей»): всё строится на звучании и вашей истории. Закрыть этот пробел может Last.fm (§10).

## 10. Что у Яндекса и при чём тут Last.fm

### Как настраивается «Моя волна» у Яндекса

* **Настройки:** «Характер» (Любимое, Незнакомое, Популярное), «Настроение» (Бодрое, Весёлое, Спокойное, Грустное), «Язык» (в том числе «Без слов»), «Занятие». С лета 2025 есть темп бега.
* **Весна 2026:** волну строит генеративная модель ARGUS по истории действий. Рекомендации стали «гиперконтекстными»: учитывают время суток, день недели и устройство. Появились «Встряхнуть» и запуск волны по свободному текстовому запросу.
* **Умные плейлисты:** «Плейлист дня»; «Дежавю» — не слышанное, но похожее на ваш вкус; «Премьера» — новинки знакомых артистов; «Тайник» — добавленное, но не прослушанное.

### Что из этого уже есть в VaginaWave

| Яндекс | VaginaWave |
|---|---|
| Характер: любимое / незнакомое | «Любимое», «Баланс», «Незнакомое» |
| Характер: популярное | заменено на «Забытое» — по сути «Тайник» прямо в волне |
| Настроение, занятие | цели по признакам AudioMuse (энергия, темп, danceable, happy, relaxed, sad и т. д.) |
| Язык: «Без слов» | тег `instrumental` MusiCNN |
| Язык: русский / иностранный | пока нет: нужен язык текста из анализа лирики AudioMuse |
| Время суток, день недели | статистика кластеров по 8 корзинам: 4 части суток × будни/выходные |
| Устройство | пишется в события (`device`), в модели пока не используется |
| Встряхнуть | `POST /api/wave/{id}/shake` |
| Волна по треку, альбому, артисту, плейлисту | `seed` в `/api/wave/start` |
| Волна по текстовому запросу | следующий шаг: CLAP-поиск AudioMuse (`/api/clap/search`) как дополнительный якорь |
| «Дежавю», «Премьера» | следующий шаг: из тех же сигналов, «Премьера» — по `getAlbumList2?type=newest` |

### AudioMuse или Last.fm

Это не «или»: они отвечают на разные вопросы.

| | AudioMuse-AI | Last.fm |
|---|---|---|
| На чём основан | на звуке ваших файлов (MusiCNN, CLAP) | на прослушиваниях миллионов людей («кто слушает X, слушает и Y») |
| Что умеет | «звучит похоже», плавные переходы, настроение и темп, похожее на весь плейлист | культурная близость: та же сцена, эпоха, тусовка, даже если звучит иначе |
| Редкие треки, локальные записи, русский андеграунд | работает с любым файлом | часто пусто: мало скробблов, путаница в написании имён |
| Знает ли о ваших пропусках | нет, это делает VaginaWave | нет, это делает VaginaWave |
| Персональные рекомендации | нет | готового метода нет: только `artist.getSimilar`, `track.getSimilar`, теги и ваша история (`user.getTopTracks`, `user.getLovedTracks`) |
| Нужен интернет и ключ | нет | да; без коммерческого использования |

**Вывод.** AudioMuse остаётся основой: без него не работают ни плавность, ни настроения, ни «похоже на весь плейлист». Last.fm стоит добавить вторым источником кандидатов:

* кластер вкуса → его топ-артисты → `artist.getSimilar` → те из похожих артистов, что есть в вашей библиотеке;
* если вы скробблите в Last.fm из других сервисов, импорт `user.getLovedTracks` и `user.getTopTracks` даст вкусу историю за годы.

Каждое прослушивание уже помечается источником кандидата (`source`), а «Ваш вкус» показывает дослушиваемость по источникам. Поэтому вопрос «что лучше» решится на ваших собственных данных, а не на догадках.

## 11. Навигация: какие вкладки у похожих приложений

| Приложение | Вкладки и разделы |
|---|---|
| Яндекс Музыка | главная с «Моей волной» и подборками, поиск, «Коллекция» |
| Spotify | Главная, Поиск, Медиатека |
| Tempus (Subsonic, Android) | главная с полками (недавно добавлено и слушали, случайное, любимое), библиотека (артисты, альбомы, жанры, плейлисты, десятилетия), загрузки; Instant Mix, интернет-радио, подкасты; настройки: транскодинг, ReplayGain, gapless, эквалайзер, скробблинг |
| Symfonium (Subsonic, Android) | настраиваемые вкладки: главная, библиотека, поиск, настройки. Настройки по категориям: провайдеры (серверы), офлайн и кэш, интерфейс (отдельно для главной, библиотеки, альбома, артиста, плейлиста, плеера), воспроизведение (переходы, транскодинг, аудиофокус, кнопки гарнитуры), Android Auto, резервная копия |

**В VaginaWave сейчас:** Главная (волна и полки) · Поиск · Коллекция · Настройки. Настройки разбиты на категории: Сервер · Моя волна · Воспроизведение · Интерфейс · Библиотека и вкус · О приложении.

**Кандидаты на потом:**
* жанры и десятилетия в коллекции (поле `genre` уже приходит из Navidrome);
* «Загрузки» и офлайн — уже в нативном приложении;
* очередь «Далее» с перестановкой;
* редактирование плейлистов;
* таймер сна;
* эквалайзер и ReplayGain;
* волна по текстовому запросу через CLAP.

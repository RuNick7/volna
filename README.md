# Volna

Свой музыкальный клиент для [Navidrome](https://www.navidrome.org/) в духе Яндекс Музыки. Главный экран — одна кнопка «Моя волна»: нажали, и дальше бесконечно идёт музыка, которую вы с высокой вероятностью дослушаете. Каждый пропуск сразу смещает веса, и волна уходит от того, что вам сейчас не заходит.

Звучание треков анализирует [AudioMuse-AI](https://github.com/NeptuneHub/AudioMuse-AI). Историю, лайки и прослушивания хранит Navidrome, поэтому они общие для всех клиентов.

## Что в репозитории

| Папка | Что это |
|---|---|
| [`wave-service/`](wave-service) | Прототип сервиса волны (Python, FastAPI) и веб-плеер к нему |
| [`docs/architecture.md`](docs/architecture.md) | Архитектура: алгоритм волны, продолжение плейлистов, синхронизация, план |
| [`docs/design.md`](docs/design.md) | Визуальный язык: чёрный фон, белые элементы, топографические линии-волны |

Android-приложение — следующий этап. Оно будет ходить в тот же API, что и веб-плеер.

## Быстрый старт: демо без сервера

В демо-режиме вместо Navidrome и AudioMuse работает синтетическая библиотека (около 600 треков, 8 жанров, сгенерированный звук). Этого хватает, чтобы потрогать волну и проверить алгоритм.

```bash
cd wave-service
python3 -m venv .venv
.venv/bin/pip install -e '.[dev]'
.venv/bin/python -m volna --demo
```

Откройте <http://127.0.0.1:8765> и нажмите на круг.

Управление: пробел — пауза, `→` — дальше, `L` — нравится, `D` — не нравится, `S` — встряхнуть волну.

## С вашим Navidrome и AudioMuse

```bash
cd wave-service
cp .env.example .env    # впишите адреса, логин Navidrome и API_TOKEN AudioMuse
.venv/bin/python -m volna
```

Нужно, чтобы AudioMuse уже проанализировал библиотеку: треки без анализа в волну не попадают. Проверка связи: <http://127.0.0.1:8765/api/health>.

> В прототипе нет авторизации. Чтобы слушать с телефона, задайте `VOLNA_HOST=0.0.0.0` и открывайте только в домашней сети, не публикуйте порт в интернет.

## Из чего складывается вкус

Раз в 6 часов сервис синхронизирует всю библиотеку Navidrome. Это история и отметки, общие для всех клиентов: веб-интерфейса Navidrome, других плееров и самого Volna.

| Сигнал | Откуда | Что даёт |
|---|---|---|
| Сколько раз и когда играл каждый трек | Navidrome, `playCount` и `played` | вес трека `log(1 + прослушивания)`, затухает с полупериодом 120 дней; плюс «дослушивания» артиста |
| ★ трека, оценка 1–5 | Navidrome | ★ даёт +3; 5★ +3, 4★ +1.5, 2★ −1; 1★ — трек больше не звучит |
| ★ альбома, оценка альбома | Navidrome | +1 каждому треку альбома, альбом считается любимым; 1★ — альбом не звучит |
| ★ артиста, оценка артиста | Navidrome | +0.6 пятнадцати самым слушаемым трекам артиста, артист считается любимым; 1★ — артист не звучит |
| Ваши плейлисты | Navidrome | +0.8 каждому треку, затухает с давностью изменения плейлиста |
| Дослушал, пропустил (и на какой секунде), лайк, «не нравится» | события Volna — в волне, альбоме, плейлисте, поиске | веса треков, статистика артистов и альбомов, успех кластеров вкуса по времени суток и будням/выходным |

### Как волна реагирует на пропуски

| Что вы сделали | Что меняется сразу | Что меняется надолго |
|---|---|---|
| Дослушали (≥ 80 %) | вектор сессии сдвигается к треку, кластер чуть усиливается | +1 к весу трека, плюс артисту и альбому, успех кластера в это время |
| Пропустили до 30 с или до 25 % трека | вес кластера ×0.6, из очереди убираются похожие треки и тот же артист, вектор сессии отталкивается | −1.5 к весу трека, минус артисту и альбому; после двух ранних пропусков трек «отдыхает» |
| Два ранних пропуска подряд | волна переключается на другой кластер вкуса | — |
| Пропустили позже | вес кластера ×0.85 | −0.4 к весу трека |
| «Не нравится» | как ранний пропуск, только сильнее | 1★ в Navidrome, трек больше не звучит |
| «Нравится» | кластер и вектор сессии заметно усиливаются | ★ в Navidrome, +3 к весу трека |

Что система уже узнала, видно в настройках, в блоке «Ваш вкус»: кого вы дослушиваете, кого пропускаете и из какого источника треки заходят лучше.

## Настройки волны

Настройки сделаны по образцу яндексовских и открываются кнопкой под главным кругом. Музыка при смене настроек не прерывается: пересобирается только очередь.

| Настройка | Варианты | Как работает |
|---|---|---|
| Характер | Любимое · Баланс · Незнакомое · Забытое | доля знакомого и нового. «Забытое» — отмеченное и любимое, что давно не звучало (аналог яндексовского «Тайника»); вместо «Популярного», которое для одной домашней библиотеки почти бессмысленно |
| Настроение | Бодрое · Весёлое · Спокойное · Грустное | цели по энергии, темпу и шкалам настроения AudioMuse |
| Занятие | Просыпаюсь · В дороге · Работаю · Тренируюсь · Засыпаю | то же, с другими целями |
| Без слов | вкл/выкл | предпочтение треков с тегом `instrumental` из MusiCNN |
| Смелость подбора | 0.1–1.5 | температура выдачи AudioMuse и доля разведки в другие кластеры вкуса |
| Разнообразие | 0–100 % | насколько порция не должна повторять одно звучание и как быстро кластер «приедается» |
| Не повторять треки | 0–60 дней | окно, в течение которого недавно игравшее не возвращается |
| Время суток и выходные | вкл/выкл | учитывать ли, что утром в будни заходит одно, а вечером в субботу — другое |
| Встряхнуть волну | кнопка или `S` | уйти от текущего звучания и пару порций смелее исследовать вкус |

Ещё есть волна «по» треку, альбому, артисту или плейлисту. Она якорится на выбранном элементе, а не на общем вкусе.

Подробнее об алгоритме — в [docs/architecture.md](docs/architecture.md) и в docstring-ах [`engine.py`](wave-service/volna/engine.py).

## Проверка

```bash
cd wave-service
.venv/bin/python -m pytest
.venv/bin/python scripts/simulate.py
```

Симуляция гоняет виртуального слушателя по демо-библиотеке:

* **Волна держит около 78 % дослушанного** (максимум для этого слушателя около 80 %), а разлюбленный жанр почти не звучит.
* **Если слушатель разлюбил жанр,** который в истории был любимым, его доля падает с 14 % в первых 10 треках до 4 % в следующих 20 — прямо в первой же сессии.
* **Продолжение плейлиста из двух жанров** держит баланс жанров 94 %, а «радио по последней песне» — 0 %: оно целиком уходит в жанр последнего трека.
* **Настройки меняют звучание.** Средняя энергия: «Спокойное» — 0.20, «Бодрое» — 0.70, без настроек — 0.41. «Без слов» поднимает долю инструментального до 95 %. Новых треков: «Любимое» — 25 %, «Незнакомое» — 95 %.

## API

| Метод | Что делает |
|---|---|
| `POST /api/wave/start` `{settings?, seed?, device?}` | запустить волну; `seed: {type: track\|album\|artist\|playlist, id}` — волна «по» элементу |
| `POST /api/wave/{id}/advance` `{track_id, outcome, position, duration}` | трек закончился (`complete`), пропущен (`skip`), «не нравится» (`dislike`) или не играет (`error`); в ответ — следующий трек |
| `POST /api/wave/{id}/like` `{track_id, liked}` | лайк текущего трека в волне (звезда в Navidrome и усиление кластера) |
| `POST /api/wave/{id}/settings` `{…}` | поменять настройки на ходу; они же сохраняются по умолчанию |
| `POST /api/wave/{id}/shake` | встряхнуть волну |
| `GET /api/wave/{id}/debug` | как сместились веса кластеров в этой сессии |
| `GET`/`PUT /api/settings` | сохранённые настройки и допустимые значения |
| `POST /api/continue` `{track_ids}` | продолжить плейлист похожим на весь плейлист |
| `POST /api/events` `{track_id, outcome, position, duration, context_type, context_id}` | прослушивание вне волны (альбом, плейлист, поиск) — тоже учит вкус |
| `POST /api/like` `{type: track\|album\|artist, id, liked}` | лайк трека, альбома или артиста |
| `GET /api/taste` | «Ваш вкус»: кластеры, любимые и пропускаемые артисты, дослушиваемость по источникам |
| `GET /api/stream/{id}`, `GET /api/cover/{id}` | аудио и обложка через сервис (логин Navidrome не уходит в браузер) |
